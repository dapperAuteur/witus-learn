# Docs notes: feat/admin-branding (for the bundle integrator)

This branch deliberately does not touch `README.md` or `src/lib/roadmap.ts` (other branches in
the Admin/Operator workstream edit both; the bundler folds these sentences in once).

## README sentence (for the admin/settings feature list)

> Brand admins self-serve the full brand identity at `/admin/settings`: name, tagline, accent
> colors, wordmark, PWA short name, theme color, logo, favicon, and the default social card,
> each with a live preview and https-only URL validation; a server-rendered "Saved brand" card

## Theme keys: verified-consumed vs skipped (authoritative-values audit)

Every exposed key was verified to render somewhere before being added to the form:

| Key | Consumer | Exposed |
| --- | --- | --- |
| `theme.name` | `brandName()` in `src/lib/branding.ts` (was already exposed via Name) | already |
| `theme.colors.accent/accentFg` | tenant layout, login, OG route, embeds | already |
| `theme.wordmark` | site header (`src/components/site-header.tsx`) | new |
| `theme.shortName` | PWA manifest `short_name` (`src/app/manifest.webmanifest/route.ts`) | new |
| `theme.logoUrl` | manifest icons + JSON-LD Organization logo (`src/lib/seo/json-ld.ts`) | new |
| `theme.faviconUrl` | metadata icons (`src/lib/branding.ts`) | new |
| `theme.ogDefaultUrl` | default social card (`src/lib/branding.ts`) | new |
| `theme.themeColor` | viewport theme-color, manifest `theme_color`, accent fallback | new |
| `theme.manifestUrl` | metadata manifest override (`src/lib/branding.ts`) | **not exposed** |

`manifestUrl` is consumed but intentionally left out of the self-serve form: the generated
`/manifest.webmanifest` already reflects logo, short name, and theme color, and replacing the
whole manifest with an external URL is an easy way for a brand admin to break installability.
It remains a DB-level escape hatch (noted in `src/lib/theme-settings.ts`).

There is no "OG subtitle" theme key: the default card is generated by `/api/og` from the
tenant's own name and accent, and page-level cards pass their own title/subtitle. Nothing to
expose, nothing skipped.

## No migration

`tenants.theme` is `jsonb` (`src/db/schema/tenancy.ts`); new keys need no schema change and no
`pnpm db:migrate:prod`.

## Gating

Unchanged and uniform: the settings page requires `requireBrandAdmin(tenant.id)` and the PATCH
requires `isTenantAdmin` (brand admin of the resolved tenant, or the platform owner). The new
fields sit behind exactly the same gate as the existing ones; no per-field distinction exists
today and none was introduced.
